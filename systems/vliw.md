# VLIW（Very Long Instruction Word，超长指令字）

> 相关笔记：[SIMD / SIMT](simd-simt.md) | [CPI](cpi.md) | [寄存器](register.md)

## 是什么

编译器把多条独立指令打包成一条超长指令，硬件一个周期同时执行。并行发现从硬件移到编译期。

## 超标量 vs VLIW

| | 超标量 | VLIW |
|------|------|------|
| 并行发现 | 硬件动态 | **编译器静态** |
| 硬件复杂度 | 高（乱序、分支预测） | 低（顺序执行） |
| 二进制兼容 | 跨代兼容 | **换硬件重编译** |
| 代码密度 | 好 | 差（NOP 多） |
| 主战场 | 通用 CPU | DSP、AI 加速器 |

## 指令结构

```
[ ADD R1,R2,R3 | LOAD R4,[R5] | MUL R6,R7,R8 | NOP ]
  编译器确认这四个操作无依赖，硬件同时执行
```

NOP 填充空闲槽 → 代码体积大。

## 为什么没统治通用 CPU

最大的短板：**二进制不兼容**。指令宽度和槽位由硬件决定，换芯片必须全部重编译。Intel Itanium 是 VLIW 最惨痛的失败。

但它活在 DSP 和 AI 加速器里：编译器知道微架构，不需要乱序调度，芯片面积全给计算单元。

## 并行模型关系

```
超标量: 硬件找并行 → CPI < 1
SIMD:   一条指令多数据
SIMT:   一条指令多线程（GPU Warp）
VLIW:   一条指令多操作（编译器找并行）
```
