# 寄存器（Register）

> 相关笔记：[CPI](cpi.md)

## 定义

CPU 内部最快、最小的存储单元。存储金字塔顶层——唯一能与 ALU 同周期交互的存储器。

## 为什么必须存在

如果运算直接读写内存（200+ 周期），ALU 每算一次等 200 周期 → CPI = 200+。

寄存器作为 ALU 和内存的缓冲层——频繁访问的数据钉在离 ALU 最近的地方。

## RISC Load-Store 架构

> 只有 Load/Store 指令可以访存，所有运算只操作寄存器。

```
LDR X1, [X0]      ← Load: 内存 → 寄存器
ADD X2, X1, X3    ← 运算: 寄存器 + 寄存器
```

x86（CISC）允许运算直接访存，但内部拆成 micro-ops 先 load 再算，本质相同。

## Register File

小型多端口 SRAM 阵列，通常 2R1W（两读一写）。一个周期内同时读两个源操作数 + 写一个结果。

```
              ┌──────────────────┐
R1 addr ──→   │                  │ ──→ R1 data
R2 addr ──→   │   Register File  │ ──→ R2 data
W  addr ──→   │   (32 × 64bit)   │ ←── W data
              └──────────────────┘
```

超标量 N 发射需要 2N 读 + N 写端口 → 面积暴增 → CPU 设计的核心瓶颈之一。

## 寄存器数量

| 架构 | 通用寄存器数 | 备注 |
|------|-------------|------|
| x86-64 | 16 | 历史上仅 8 个 |
| ARM64 | 31 | + SP/ZR |
| RISC-V | 32 | X0 硬连线为 0 |

不是越多越好：每多一倍 → SRAM 面积翻倍 + 寻址位增多 + 指令编码变宽。RISC-V 用 5 bit 编码寄存器号 → 上限 32 个。
