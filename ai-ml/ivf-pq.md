# IVF-PQ 索引

大规模向量索引最常用的组合方案。IVF 解决「搜得快」，PQ 解决「存得下」。

## IVF（Inverted File Index，倒排索引）

核心思想：**先粗筛，再细排**，避免全量暴力搜索。

| 阶段 | 操作 |
|------|------|
| 训练 | K-means 将全量向量聚为 K 个簇，每个簇有 centroid |
| 建索引 | 每个向量归到最近簇，建立「簇 → 向量列表」倒排表 |
| 搜索 | 只需搜 nprobe 个最近簇，而非全部 K 个 |

搜索复杂度从 O(N) 降到 O(N × nprobe / K)。增大 nprobe 可换精度。

## PQ（Product Quantization，乘积量化）

核心思想：**用短码压缩向量**，大幅降低内存。

1. 将 d 维向量切成 m 段，每段 d/m 维
2. 每段独立 K-means 聚类（通常 256 中心 → 1 字节编码）
3. 每个向量压缩为 m 字节（原始 d × 4 字节 → 压缩 10~30 倍）
4. 搜索时查表计算近似距离（Asymmetric Distance Computation）

代价：距离计算变为近似值，精度有损。

## IVF-PQ 组合

```
IVF（剪枝）+ PQ（压缩）= 亿级向量 + 毫秒级查询 + GB 级内存
```

### 搜索流程

1. IVF 粗排：找到 q 最近的 nprobe 个簇中心
2. 在候选簇的倒排列表中，用 PQ 编码做近似距离计算
3. 返回近似的 top-k

### 典型数据

1 亿条 128 维 float32 向量：原始 51.2 GB → IVF-PQ 压缩后约 1~2 GB，查询延迟毫秒级。

### 相关算法

- **ScaNN**（Google）：各向异性量化，在 PQ 基础上优化内积距离的精度
- **IVF-PQ + HNSW**：用 HNSW 图代替 K-means 做粗排，更快但更耗内存
- **DiskANN**：将图索引放在 SSD 上，内存只缓存关键节点，进一步降低成本
