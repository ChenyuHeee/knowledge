# MCTS + PRM 架构

> 相关笔记：[RL 概述](rl-intro.md)

OpenAI o1/o3、DeepSeek-R1 等「慢思考」模型的底层框架。将 AlphaGo 的搜索思路搬到 LLM 推理上。

## 背景：快思考 vs 慢思考

| 快思考 (System 1) | 慢思考 (System 2) |
|------|------|
| GPT-4 / LLaMA | o1 / R1 |
| 直接吐 token | 内部搜索多条路径再输出 |
| 秒级 | 困难题慢几分钟 |

## MCTS（蒙特卡洛树搜索）

AlphaGo 核心算法。不在巨大空间穷举，而是只往最可能赢的分支深挖。

### 四步循环

1. **Selection（选择）**：从根沿树走，每次选最有潜力子节点（UCB = 胜率 + 探索度）
2. **Expansion（扩展）**：到叶节点后展开新子节点
3. **Simulation（模拟）**：从新节点快速推到终局（LLM 场景：继续生成到答案）
4. **Backpropagation（回传）**：终局结果沿路径更新所有祖先节点

循环几千次，选访问最多或胜率最高的路径。

### LLM 场景的树结构

```
根: 空答案
一层: 第一步推理
二层: 第二步推理
...
叶: 最终答案
```

## PRM（过程奖励模型）

### ORM 的局限

传统 RLHF 的 ORM 只看最终答案：
`步骤1 → 步骤2 → 步骤3 → 答案 → 0.9 分`

中间某步就错了但无法阻止，必须推到终点才知道。

### PRM 的做法

每步都打分：`步骤1:0.95 | 步骤2:0.88 | 步骤3:0.12 ✗` → 在步骤 3 就剪枝，不必推到终点。

训练方式：人类标注每步正确性，或模型自动标注（正确路径混入随机错误，标记各步对错）。奠基工作：OpenAI Let's Verify Step by Step (2023)。

## MCTS + PRM 组合

```
MCTS 选路径 → PRM 评步骤 → 回传分数 → 重新选路径 → 循环
```

MCTS 负责在树里找路，PRM 在中间判断路好不好。两个引擎互相配合。

## 与 RL 知识链

```
RL → MCTS → PRM → MCTS+PRM (o1/R1) → RLVR (下一步)
```

RLVR（Reinforcement Learning with Verifiable Rewards）：数学题答案对错可验证，不需人类标注，可能替代 RLHF 的部分场景。
