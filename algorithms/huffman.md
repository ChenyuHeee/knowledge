# 霍夫曼算法（Huffman Coding）

## 直觉

高频字符用短码，低频字符用长码，减少总编码长度。

```
A(50%): 0       (1 bit)
B(30%): 10      (2 bit)
C(15%): 110     (3 bit)
D(5%):  111     (3 bit)

定长 100 字符 = 800 bit → 霍夫曼 = 170 bit (21%)
```

## 算法步骤

```
1. 每个字符独立节点，权值 = 频率
2. 重复直到只剩一个节点：
     a. 取权值最小的两个节点
     b. 新建父节点，权值 = 两子之和
     c. 左子标 0，右子标 1
3. 根到字符的路径 = 编码（前缀码：无人是另一人的前缀）
```

### 手动演算

```
初始: A(50) B(30) C(15) D(5)

合并 C+D → 20:      A(50) B(30) [20]
合并 B+20 → 50:      A(50) [50]
合并 A+50 → 100:     [100]

树:
     root(100)
    /0       \1
  A(50)     inner(50)
           /10     \11
         B(30)    inner(20)
                 /110   \111
               C(15)    D(5)

编码: A=0, B=10, C=110, D=111
```

## 最优性证明（贪心正确性）

目标：最小化加权路径长度 $\sum f_i \times L_i$。

**引理**：频率最低的两个字符在最优树中一定是最深的叶子且共享父节点。

理由（反证）：如果最优树中不是它们最深，交换一个更深但频率更高的字符到底层 → 加权路径长度减小 → 矛盾。

合并最小两个 → 问题规模 -1 → 递归 → 全局最优。

## 与 BPE Tokenizer 的关系

| | 霍夫曼 | BPE |
|------|--------|-----|
| 粒度 | 字符 | 子词 |
| 统计 | 单字符频率 | 字节对共现 |
| 合并对象 | 最小频率 | 最大频率对 |
| 目标 | 最短编码 | 最少 token 数 |

BPE 是霍夫曼思想在 NLP 中的延伸——同一个贪心哲学，统计不同粒度的符号频率，合并策略不同但目标一致。
